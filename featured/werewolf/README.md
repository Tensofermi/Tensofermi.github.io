# 夜议 · AI 狼人杀

荧邀请朋友们围桌玩狼人杀。你占一个席位，其余由 AI 扮演。GitHub Pages 直接从个人站仓库提供静态页面。Featured 的 Games 区只放链接，进入此目录后才加载游戏。可用任何静态 HTTP 服务预览。示例命令在仓库根目录运行。

```sh
python -m http.server 8000
node --test featured/werewolf/*.test.mjs
```

在浏览器打开 `http://localhost:8000/featured/werewolf/`。试玩使用本地规则机器人。模型模式使用兼容 Chat Completions 的接口，需要模型名、API Key 和允许浏览器跨域访问的服务。设置会显示请求目的地。Key 只在本次页面内存中使用，刷新后继续模型局需要重新输入。已保存的模型局也可以切换到试玩继续。

## 一局如何推进

- 6 人局有 2 狼、2 村民、1 预言家和 1 女巫。9 人局有 3 狼、3 村民、1 预言家、1 女巫和 1 猎人。12 人局有 4 狼、5 村民、1 预言家、1 女巫和 1 猎人。
- 每张公开角色卡固定一位朋友的说话方式、风险偏好和推理习惯。6 人和 9 人从 11 位朋友中抽取所需席位，12 人全员入席。朋友座次和牌局身份独立洗牌。默认角色头像采用允许转载或署名使用的同人插画，名片链接到画师原帖。玩家可以选择荧或通用头像，也可以为角色上传头像。上传的头像只保存在当前浏览器。
- 夜间先进行一次狼队发言，每名活狼最多发一次。狼刀以队内同组投票决定，平票取席位号最小的目标。随后预言家查验，女巫用药。
- 女巫每局有一瓶解药和一瓶毒药，每夜至多用一瓶。首夜可自救。解药抵消狼刀，毒药导致出局。猎人中毒时无法开枪。
- 无警长。主持人每天抽签决定沿圆桌顺时针或逆时针发言，跳过出局席位。昨夜有人出局时，以其中最小号为起点，从该方向相邻的第一位存活玩家开始。平安夜从随机抽中的存活玩家开始。主持人在天亮时公布起点和次序。
- 所有存活席位进行首轮放逐投票。最高票并列的候选人依当天原顺序各发言一次，由台下存活席位对候选人加投。再次平票或台下无人时不放逐。较早版本的存档保留本局原本的发言和投票规则。
- 放逐者先留遗言，再结算猎人技能。夜间出局和被猎人带走的席位没有遗言。死亡按固定顺序结算，复盘揭示身份和夜间行动。
- 完成遗言和技能连锁后判定胜负。狼全灭则好人获胜。活狼达到或超过活好人人数则狼人获胜。
- 默认手动逐条阅读。天亮、发言、票型、放逐和终局各占一条或一组可见事件。自动播放按文字长度留出时间，快速展示跳过阅读等待。刷新后保留已读位置。

## 修改位置

| 修改 | 文件与约定 |
| --- | --- |
| 角色、夜间顺序、结算、胜负 | `roles.mjs` 保存配置和说明，`rules.mjs` 负责新建局、推进阶段、列出合法行动及提交。新增角色时同时添加行动类型、权威校验、可见性分支和页面控件。以规则测试保护新技能与既有技能的结算顺序。 |
| 哪个席位能知道什么 | `visibility.mjs` 的 `observe` 是唯一给模型输入和人类现场界面供数的通道。更新信息时逐一核对各身份。狼队私聊、查验、狼刀目标的可见规则都在这里。 |
| 角色卡、头像、提示词、发言长度 | `characters.mjs` 定义公开角色与备用图标。`portraits.mjs` 保存默认头像的路径与画师来源。AI 的系统提示词、行动结构和私有记忆在 `ai.mjs`。约束发言长度时同步修改规则校验和输入控件。 |
| 请求格式和服务 | `model.mjs` 将消息和输出上限转换为模型请求。适配器提供 `generate(messages, {signal, maxTokens})` 和 `test({signal})` 两个异步方法。可以换成向自有代理发请求的适配器。 |
| 并发、预算、异常恢复 | `scheduler.mjs` 的 `DEFAULT_LIMITS` 控制每局模型调用次数、并发、输入长度、输出长度、修复尝试。调整历史截断、观察摘要、私人判断时一起检查 `ai.mjs`。调度器通过 `observe` 构建每次请求，模型提议仍由引擎验证。 |
| 保存、恢复、暂停 | `save.mjs` 包含存档版本和可写字段。 `app.mjs` 将规则、调度器、界面和存档连接起来。更改存档形状时应同步修改读取校验和版本处理。 |
| 提交和回放 | `view.mjs` 只接收人类可见视图。 `playback.mjs` 从可见事件建立阅读队列， `app.mjs` 管理手动推进、自动播放与存档。密语和私人观察与公开日志分开。 |

终局的观察检查显示最近一份实际发送给每个席位的模型消息。这份记录也可通过明确开启的开发模式查看。试玩席位没有向外部模型发送请求。模型计数和服务报告的 token 在复盘中显示，费用未配置定价时省略。
